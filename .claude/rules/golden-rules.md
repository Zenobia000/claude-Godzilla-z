# Golden Rules

這裡只放所有任務都必須遵守、跨技術棧仍成立的規則。方法論、格式、清單與領域知識屬於 Skills，不在 Rules 重複。

## 1. 來源優先，假設透明

- 先讀取使用者指定的來源、現有程式碼、測試與專案文件，再提出方案或修改。
- 不以 AI 推論覆蓋已核准的需求或決策；來源衝突時指出衝突並確認權威來源。
- 無法由證據確認的內容，標記為「假設」「待確認」或「TO-BE」，不得寫成既成事實。

## 2. 保持可追溯

- 需求、驗收、設計、實作、測試與證據之間使用穩定 ID 關聯，不靠標題或顯示群組猜測。
- 從試算表匯入時保留 `source_file`、`sheet`、`row`、`cell/range` 與來源列 ID；衍生文件不得抹除來源。
- 區分需求／文件狀態、程式碼現況與驗證證據；計畫或 code map 不等於完成。

## 3. 保護使用者工作與敏感資訊

- 保留既有變更，不覆寫、不刪除、不還原不屬於當前任務的工作。
- 破壞性、不可逆或會影響外部系統的動作，必須先確認精確範圍與授權。
- 不提交秘密、憑證、個資或敏感營運資料；發現疑似曝露時停止擴散並清楚回報。

## 4. 以證據宣告完成

- 依變更風險執行最接近實際行為的驗證；不得把未執行的檢查描述為通過。
- 回報實際執行的指令、結果、未驗證項目與殘餘風險。
- 驗收標準、測試與證據對不上時，狀態保持未完成或受阻。

## 5. 最小必要變更

- 優先沿用專案既有架構、慣例與工具；避免與目標無關的重構或新依賴。
- 文件深度依風險與交付階段調整，不為了填滿模板而製造內容。
- 只有需要隔離權限、獨立 context、平行探索或專業驗證時才使用 Subagent。
