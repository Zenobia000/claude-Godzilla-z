# 白話回答（Plain-Language Answers）

管**對話**的語域——「回答眼前這個人」時該講到哪一層。文件的語域走 [`language-register.md`](language-register.md)；確定要白話之後**怎麼寫**（步驟、檢查表、反模式）走 `skills/sunnydata-plain-explain`。

## 核心原則

**白話不是簡化，是把答案翻譯到讀者的決策層。**

| 停在哪 | 講出來長這樣 | 讀者能做什麼 |
| :--- | :--- | :--- |
| 實作層 | 「追溯矩陣裡 REQ-014 的 ACPT 欄是空的」 | 要先自己翻譯一次才知道關不關他的事 |
| **決策層** | 「REQ-014 沒有驗收條件，Gate 會擋它——但它排在下個階段，這週不影響你」 | **直接知道要不要動作** |

停在實作層不是比較嚴謹，是**把翻譯的工作丟給讀者**。而讀者若翻錯，代價由他承擔。

## 何時必須切白話

任一條成立就切：

1. 使用者明說：「白話」「講重點」「太長」「所以呢」「結論是什麼」。
2. 使用者問的是**決策問題**（有沒有規劃／會怎樣／影響是什麼／該不該做），而不是**定位問題**（在哪實作／哪個函式／哪一行）。
3. 答案要跨層：從實作細節推導到「對進度、對風險、對今天要做什麼」的影響。
4. 使用者當下不在工程 context——問的是需求、範圍、驗收、流程。

## 何時**不可以**白話

這幾種場合的精確性本身就是內容，退化成白話等於毀掉可追溯性：

- 使用者要的是定位（他要去改那段 code）。**這條同時是與 `skills/adhd-dev-mode` 的仲裁**：該 skill 要求給 `file:line` 與確切指令，白話的「用動作講機制、不用元件名」只在決策問題成立時適用，兩者不衝突。
- 寫進**文件**的內容——走 `language-register.md` 的 L1/L2/L3。
- 需要留下可驗證證據的產出：commit message、PR body、驗收報告、ADR、缺口登記。
- 安全／不可逆的操作指示——步驟必須精確到可照做，不可為了順口而模糊。

## 換的是表層，不是證據

白話可以省路徑、行號、識別字、grep 命中數、推導過程。**不能省誠實、比例與決策**：沒驗證過就說沒驗證過；不把小事講成災難、也不把真風險講輕；講完要讓對方知道下一步是什麼，或明說「不需要動作」。結論可以不附路徑，但被追問時必須拿得出來。
