# Playbook

> 用法在這裡。結構定義在 [WORKFLOW.md](WORKFLOW.md)，不重述。

## 開工前只問一句

**「做完長什麼樣」，你現在講得出來嗎？**

| 答案 | 走 |
|---|---|
| 講得出來，而且很小 | [A：直接做](#a直接做) |
| 講得出來，是一個功能 | [B：規劃一輪](#b規劃一輪) |
| **講不出來** | [C：先撥霧](#c先撥霧) |

> 連這句話都還沒跟人對過：[`00` 需求護身符](../VibeCoding_Workflow_Templates/00_requirements_amulet.md) 的 §3.2／§4.2 各八題 ＋ 開場檢查表，十分鐘跑完就有輪廓。**它只管問對問題，不產文件**，跑完會把你送回這張表。

---

## A：直接做

```
開分支 → 做最小可動的東西 → 跑起來看 → 打掉或往下
```

**不能省的只有兩件**：先開分支、回不了頭的決策寫 ADR（要過三條件閘，見下）。

其他全部不用：規劃、切片、覆蓋率、文件。

**離開這條路的訊號**：你開始記不住做過哪些決定，或東西要交給別人。

## B：規劃一輪

`▸` = 一個 session 邊界。

### ▸ 1 — 探索到切片（**不能中斷**）

載入 `sunnydata-design`，Phase 1 → 2 一口氣走完。

兩個最常被跳過、但決定後面順不順的：

| 步驟 | 規則 |
|---|---|
| **定接縫** | 載 `sunnydata-codebase-design`。沿用既有 > 新開；用**能觀測到行為的最高**接縫；越少越好（理想 1 個）。**先確認再寫第一個測試** |
| **切片** | 縱切穿過所有層。四判準：完整、可獨立驗證、**塞得進一個新 context**、接縫已定。prefactor 排最前 |

改共用型別這種爆炸半徑大的 → 不要硬塞成一片，走 expand → migrate 分批 → contract。

> 為什麼不能中斷：這幾步互為前提。中途 compact，切片會建立在摘要過的推導上。逼近 ~120k 就寫進計畫檔、開新 session。

### ▸ 2..N — 每片一個 session

```
新 context → 讀這片的計畫 → TDD at 已確認接縫 → 跑測試 → commit
```

### ▸ 收尾

`sunnydata-code-review` 兩軸 → `sunnydata-branch-lifecycle` 開 PR。

**兩軸不合併看**：Standards 與 Spec 分開報、不排名。「規範全過但做錯東西」是最貴的失敗，合併就看不見。

## C：先撥霧

`sunnydata-wayfind`。**只產決策，不產交付物。**

```
▸ 1     命名終點 → 廣度掃描 → 建 ticket → 連依賴 → 派 research 子代理 → 停
▸ 2..N  一個 session 解一張 → 寫答案 → 更新地圖
▸ 清楚了 交棒 sunnydata-design
```

**兩個最容易搞錯的**：

1. 把霧預先切成 ticket 大小。判準是「現在能不能把問題**講精準**」，不是能不能回答。
2. 一個 session 想解好幾張。狀態活在地圖裡，不活在 context 裡。

**想直接動手的衝動 = 已走到地圖邊界、該交棒**，不是可以加速。

> 這是最重的流程。握得住的功能走 B 就好。

## 卡住時查這裡

| 情況 | 動作 |
|---|---|
| 答案在**人**身上 | `sunnydata-questionnaire`，別自己猜；題庫取[護身符](../VibeCoding_Workflow_Templates/00_requirements_amulet.md) §3.2／§4.2 |
| 講不出「做完長什麼樣」 | `sunnydata-wayfind`，別開工 |
| 「該長什麼樣」爭不出來 | 做丟棄式原型；決策折回真碼，原型丟掉 |
| 一片塞不進一個 context | 切太粗，回去重切 |
| 要在計畫外的位置寫測試 | 那是新接縫，先確認 |
| 規劃逼近 ~120k | 寫下結論、開新 session |
| 工作樹有不認得的變更 | **停**，問人 |
| 想開 ADR | 三條件缺一就不寫（見下） |

**ADR 三條件**：難以逆轉 ∧ 沒有背景會困惑 ∧ 真實取捨的結果。ADR 的價值來自稀有。

## 別做這些

| 反模式 | 改成 |
|---|---|
| 一個 session 從規劃做到實作完 | 邊界斷開，切片各自新 context |
| 跳過接縫確認直接寫測試 | 接縫是規劃階段的產出 |
| 橫切（先做完 schema 層再做 API 層） | 縱切，每片穿過所有層 |
| 為顯而易見的選擇開 ADR | 三條件缺一不寫 |
| 預載整個 skill 庫求「完整」 | 只載當前步驟要的 |
| 小改動也跑完整規劃 | 走 A |
| 兩軸 review 合成一份排名 | 分開報，不排名 |

## 多 session

**安全平行**：不同切片（依賴不相交）、research ticket、唯讀審查 agent。
**不安全**：同檔案寫入、同分支 git 操作。git 寫操作前先驗 ref。

## 什麼時候換 Pilot 線

任一成立就換到 `refactor/document-driven-ecosystem`：

- 需求由**別人**拍板，要證明某範圍是誰在何時核准
- 對外交付，驗收條件必須逐條可稽核
- 多人多團隊，「這條需求有沒有測到」要查得出來
- 有法規或稽核要求

前置判斷在[護身符 §5.A 權責](../VibeCoding_Workflow_Templates/00_requirements_amulet.md)：需求 owner 與業務驗收簽核的人不是你，通常就已經命中上面某一條。

**先雛型 → 打掉 → 重構是正常路徑。** 別用 production 標準卡雛型，也別用雛型標準交付 production。

## ⚠ 尚未實測校準

- 切片大小判準（「塞得進一個 context」）是估的
- 地圖 30 張的升級門檻是估的

跑完第一輪回來改這份檔。它本來就該被實戰改寫。
