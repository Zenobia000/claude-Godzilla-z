# 模板正規標準 (Template Standard)

## 1. 六要素

| # | 要素 | 位置 |
|---|---|---|
| 1 | H1 標題 | 第 1 行：`# 文件名 (English Name) - [專案名稱]` |
| 2 | Metadata | H1 後 blockquote：`版本 | 更新 | 狀態`＋`Owner`＋`語域`＋`實例`（實例化規則，見 §2）|
| 3 | 定位宣告 | Metadata 內一句話：本文件回答什麼、不包含什麼（去哪找） |
| 4 | 目錄 | `## 目錄`：逐節連結清單，與章節同步維護 |
| 5 | 編號章節 | 一律 `## N. 標題`／`### N.M 標題`；禁止「第 N 部分」等變體 |
| 6 | 追溯段 | 最後一節：上游 ID（讀什麼來）→ 下游文件（產出給誰） |

## 2. 各要素規格

- **Metadata 的語域**依 [`.claude/rules/language-register.md`](../../.claude/rules/language-register.md) 標 L1／L2／L3；混用時標主語域。
- **定位宣告**是 MECE 邊界：明說相鄰文件的分工（例：旅程歸 ux_research、單頁歸 ui_spec）。
- **目錄**修改章節時同步更新；驗證方式見 §4。
- **追溯段**用穩定 ID（`DEC/FR/NFR/ACPT/SCN/TC-*`），不用標題文字指涉。
- **實例化規則**：每份模板宣告自己是「單例」（整個系統一份）或「每 X 一份」。多實例的分支 key 必須是**穩定錨點**——頁面、決策、Aggregate、症狀、服務——**不得以功能（feature）開資料夾分支**：狀態機屬於 Aggregate 不屬於功能，per-feature 樹會把共享領域物件切碎成互相打臉的複本。功能視角的樹已經存在：就是 `FR-* → 頁面/Aggregate/SCN` 的 ID 骨幹，索引在追蹤簿，不用資料夾再蓋一棵。

## 3. 密度紀律

- 每節＝**表格骨架＋一個範例列＋至多 2 行填寫指引**。教學、方法論、地雷長文不放模板——去 `workflow_manual.md`、Skills 或 git 歷史。
- 目標行數 **50–150**；`sad` 因承載 C4／DDD／部署多視圖，上限 **200**。`_meta/` 手冊類非填寫模板，行數豁免、六要素照辦。
- 範例值（數字、門檻、技術名）只是提示，不是專案政策。
- 同一資訊只在一份文件維護；他處用連結或 ID 引用（欄位級單一 owner）。

## 4. 合格檢查清單

- [ ] 六要素齊全，順序正確（Metadata 含實例化規則）
- [ ] 目錄與實際章節一一對應（標題、編號、順序）
- [ ] 章節編號無跳號、無變體格式
- [ ] 行數在紀律範圍內
- [ ] 交叉引用指向存在的檔案與章節（`rg` 驗證）
- [ ] 追溯段使用穩定 ID
