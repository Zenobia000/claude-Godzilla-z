## 2. 測試案例格式

| 項目 | 內容 |
| :--- | :--- |
| **ID** | TC-XXX |
| **Scenario** | [對應 SCN-*] |
| **Preconditions** | [前置狀態] |
| **Steps** | 1. … 2. … 3. … |
| **Expected Result** | [可觀察結果] |
| **Actual Result** | [執行時填] |
| **Severity / Priority** | |
| **Evidence** | Screenshot / Video / Log 路徑 |

案例清單範例：

| ID | Scenario | Steps 摘要 | Expected Result | 來源 |
| :--- | :--- | :--- | :--- | :--- |
| TC-001 | 建立工單成功 | 填必填欄位送出 | 建立成功並顯示訊息 | FR-001 |
| TC-002 | 缺少必填欄位 | 地址留空送出 | 顯示欄位錯誤 | FR-001 |
| TC-003 | 權限不足 | 一般使用者刪除工單 | 拒絕並顯示權限錯誤 | FR-*** |
| TC-004 | API Timeout | 模擬後端逾時 | 前端顯示重試提示 | NFR-*** |

## 4. 測試報告結論 (QA Report)

| 項目 | 內容 |
| :--- | :--- |
| **執行摘要** | [n 案例、通過率、未執行原因] |
| **缺陷狀態** | [開放 / 已修 / 接受風險，附 ID] |
| **殘餘風險** | [未覆蓋範圍的風險評估] |
| **上線建議** | GO / NO-GO / 條件式，附依據 |

> 只有實際執行過的測試能出現在報告裡；狀態判定交給 `/verify`。
